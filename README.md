# Creative Tech Funding Finder

Find AHRC, Innovate UK and UKRI funding for creative AI and creative technology by **who you are**: technician, practitioner, early career researcher, academic, experienced lead, doctoral student, research office or external partner. Each call shows what that person can do on it, and you can filter by purpose, funder, size, deadline and facilities.

Maintained by Rob Crow. Facts come from UKRI pages (ukri.org, the Innovation Funding Service, Innovate UK Business Connect and Gateway to Research). Always confirm on the funder's own page before bidding.

## How it works

**GitHub does all the work; Netlify only publishes.** Netlify serves the ready-made `site/` folder exactly as it is in the repository, with no build step, no forms and no functions. So it fits any Netlify plan, including the legacy free tier, and could move to GitHub Pages or a university web server unchanged.

```
data/*.json        ← THE CONTENT. Edit these. (calls, roles, ideas, past awards, status, config)
src/index.html     ← the page template (no framework)
site/              ← GENERATED by scripts/build_site.py. Never edit. Netlify publishes this.
scripts/
  validate.py      ← checks the data
  build_site.py    ← validates, then writes site/index.html with the data built in
  check_sources.py ← weekly: reads each call's page, updates dates, flags differences
  new_calls.py     ← weekly: reads UKRI's opportunities feed for new calls
  ai_draft.py      ← optional: drafts entries for new calls with the Claude API
.github/workflows/
  build.yml        ← on every push: test, validate, rebuild site/, commit it
  weekly-check.yml ← Mondays: run the checks, rebuild, open a pull request for review
.github/ISSUE_TEMPLATE/report.md ← "Report a change" form for visitors
skills/funding-finder-updater/SKILL.md ← instructions for whoever (or whichever agent) maintains it
docs/DATA.md       ← what every data field means
reports/           ← one report per weekly run
```

**The weekly loop:**

1. Every Monday, GitHub runs the checks and rebuilds `site/`.
2. **Quiet weeks publish themselves.** A week is quiet when the only changes are dates read from the funder pages, and there are no review items, broken links, possible new calls, AI drafts or open visitor reports. The result is committed to `main`, and Netlify publishes it. You don't need to do anything.
3. **Otherwise it opens a pull request** called **Weekly funding check: needs a look**, and GitHub notifies you. The description lists what needs a person. Netlify adds a deploy preview link.
4. You review and merge. Netlify then publishes it, usually within a minute.

New calls, AI drafts and anything uncertain never go live without a person merging them. To get a pull request every week instead, set `AUTO_PUBLISH: "false"` in `.github/workflows/weekly-check.yml`.

**Editing by hand** works the same way. Edit a file in `data/` on github.com (pencil icon) or locally. The **Build site** action checks it, rebuilds `site/` and commits that to the same branch. If the data has a mistake, the action fails and tells you what's wrong, and `site/` isn't touched, so the live site stays as it was.

## Setup (once, about 20 minutes)

### 1. Fill in `data/config.json`

```json
{
 "contactName": "Rob Crow",
 "repo": "<your-github-username>/creative-tech-funding-finder",
 "reportEmail": "",
 "siteUrl": "https://<your-site-name>.netlify.app"
}
```

- `repo` turns on the **Report on GitHub** button.
- `reportEmail` is optional. If set, it adds an **Email the maintainer** button. That address becomes public, so use a role or shared address if you can.
- You can fill in `siteUrl` after step 4.

### 2. Put the folder on GitHub

Using GitHub Desktop, or the terminal:

```bash
cd creative-tech-funding-finder
python3 scripts/build_site.py      # builds site/ for the first time (optional; GitHub does it too)
git init -b main
git add .
git commit -m "First version of the Funding Finder"
# Create an empty repository on github.com first (no README), then:
git remote add origin https://github.com/<you>/creative-tech-funding-finder.git
git push -u origin main
```

**Public or private?** A public repository gets GitHub Actions free, and visitors can see where the data comes from. Reports also need visitors to be able to open issues, which only works on a public repository. If it's private, reports have to come by email instead.

### 3. Repository settings

- **Settings → Actions → General → Workflow permissions**: choose **Read and write permissions** and tick **Allow GitHub Actions to create and approve pull requests**. Save.
- **Issues → Labels**: make sure a label called `report` exists. Create it if not.
- Optional: **Settings → Branches**, protect `main` so changes go through pull requests.

### 4. Connect Netlify

1. In Netlify choose **Add new site → Import an existing project → GitHub**, and pick the repository.
2. Netlify reads `netlify.toml`, so the publish directory is `site` and there's no build command. Leave the build command empty and click **Deploy**.
3. Optional: change the site name, or add a university subdomain under **Domain management**.
4. Put the final address in `data/config.json` as `siteUrl`, then commit.

### 5. Test it

- **Actions → Weekly funding check → Run workflow** runs it now. It should open a pull request.
- If most links fail at once, the job stops on purpose and saves nothing. That usually means a temporary network problem.
- The page readers were written to match the labels on UKRI's and Innovate UK's pages ("Opening date", "Closing date", "Award range", "Competition closes" and so on). They're tested against samples in `tests/`. This first live run is the real test. A page the reader can't parse is listed as "not machine-checked" for a person to look at, never guessed.

### 6. Optional: AI drafting for new calls

The scripts flag new calls but don't judge relevance or fill in the eight role descriptions. To have Claude draft those for your review in the pull request:

- add a repository secret `ANTHROPIC_API_KEY` (from console.anthropic.com);
- add a repository variable `ANTHROPIC_MODEL`, set to a current model id from https://docs.claude.com/en/docs/about-claude/models.

At up to 8 short drafts a week the cost should be small, but check current API pricing. The key stays in GitHub and never appears on the site.

## Running costs

Figures were checked 12 Oct 2026; recheck, as both companies change their pricing.

- **Netlify legacy free plan:**
  - Limits: 100 GB bandwidth and 300 build minutes a month. Hitting a limit pauses all sites on the account until you upgrade.
  - Bandwidth: this site is about 100 KB per visit, so 100 GB is roughly a million visits.
  - Build minutes: Netlify runs no build here, just a copy of `site/`, so each publish uses seconds.
  - Forms: the site doesn't use Netlify Forms, so their 100-a-month limit can't be hit.
- **Credit-based Netlify plans:**
  - Each production publish costs 15 of the Free plan's 300 monthly credits.
  - A weekly merge is about 60–75 credits a month.
  - Batch your edits into one merge.
- **GitHub Actions:**
  - Free on public repositories.
  - On private repositories, GitHub Free includes 2,000 minutes a month, and a weekly run takes a few minutes.

## Running it locally

```bash
python3 -m unittest discover tests
python3 scripts/build_site.py
python3 -m http.server -d site 8000   # then open http://localhost:8000
```

## Handing it over

The repository holds everything. A new maintainer needs:

1. **GitHub:** write access to the repository, or move the repository to a university GitHub organisation.
2. **Netlify:** the site transferred to them, or they connect the same repository to a new Netlify site of their own. The legacy free plan allows one member.
3. **API key (optional):** their own key in the `ANTHROPIC_API_KEY` secret.
4. **`data/config.json`:** updated with their name.

They can maintain it by hand, or give `skills/funding-finder-updater/SKILL.md` to their own agent (Claude or another). The skill covers reviewing the weekly pull request, adding calls and handling reports, and says never to guess a fact.
